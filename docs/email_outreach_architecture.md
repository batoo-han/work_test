# Архитектура обслуживания 1200 email-адресов для аутрича

## Контекст задачи

Обслуживание 1200 почтовых ящиков для холодного email-аутрича. Несколько клиентов, несколько направлений. Требования: минимальная стоимость инфраструктуры, высокая отказоустойчивость, устойчивая доставляемость.

---

## 1. Архитектура: три слоя

Инфраструктура строится на трёх независимых слоях, каждый из которых можно масштабировать и заменять по отдельности.

### Слой 1. Домены и DNS

**150–200 доменов** в зоне `.ru` (по 6–8 ящиков на домен). Это критически важно: один домен, попавший в спам-лист, затрагивает только 6–8 ящиков, а не всю инфраструктуру.

- **Регистратор:** Timeweb — 179 ₽ за регистрацию `.ru`, 399 ₽ продление.
- **DNS:** Cloudflare (бесплатный план) — быстрый DNS, удобное API для массового управления записями.
- **Обязательно для каждого домена:** SPF, DKIM, DMARC (начать с `p=none`, через 2–4 недели ужесточить до `p=quarantine`). Без этого Gmail, Mail.ru и Яндекс отклоняют письма на входе.

### Слой 2. Почтовые ящики

**Основной хостинг: Яндекс 360 для бизнеса** (тариф «Минимальный» — 299 ₽/мес. за пользователя).

- Подключаем домены к нескольким организациям Яндекс 360 (до 300 пользователей на организацию — 4 организации покроют 1200 ящиков).
- Яндекс обеспечивает высокую базовую репутацию IP-пулов и корректную DKIM-подпись из коробки.
- Нативная интеграция с российскими почтовыми провайдерами (Mail.ru, Яндекс) — это прямое преимущество для аутрича на российском рынке.

**Резервный хостинг (до 20% ящиков): self-hosted Mailcow на VPS Timeweb Cloud.**

- 2–3 VPS по 500–800 ₽/мес. (2 CPU, 4 ГБ RAM, NVMe) — каждый держит 80–120 ящиков.
- Полный контроль: свои IP, PTR-записи, нет чужих лимитов на отправку.
- Docker-развёртывание Mailcow — обновление одной командой, встроенный веб-интерфейс.

Разделение 80/20 между Яндексом и self-hosted даёт отказоустойчивость: при блокировке одного канала второй продолжает работать.

### Слой 3. Управление аутричем и отправка

**Платформа: Instantly** ($97/мес. — тариф Hypergrowth).

- До 100 000 писем/мес., неограниченное количество подключённых ящиков.
- Встроенный warm-up через сеть из 4.2M+ ящиков (включён в тариф, не нужен отдельный сервис).
- Автоматическая ротация ящиков отправки (inbox rotation) — нагрузка распределяется равномерно.
- Отслеживание открытий, ответов, отписок, bounce.

**Дополнительно для российских провайдеров:** Trigga (от 2 990 ₽/мес.) или Coldy — warm-up с пулом реальных ящиков Яндекса и Mail.ru. Instantly хорошо прогревает через Gmail/Outlook, но для Яндекса/Mail.ru нужен локальный пул.

## 2. Ротация и мониторинг

| Механизм | Реализация |
|---|---|
| **Ротация ящиков** | Instantly автоматически распределяет отправки между подключёнными ящиками. Настраивается лимит 30–50 писем/день на ящик. |
| **Ротация доменов** | Ящики распределены по 150–200 доменам. При деградации репутации домен выводится из ротации на «отдых» (7–14 дней). |
| **Warm-up** | Постоянный фоновый прогрев всех ящиков. Для новых ящиков — 14-дневный рамп: 30→50→80→120 писем/день. |
| **Мониторинг доставляемости** | Postmaster Tools (Google, Mail.ru), встроенная аналитика Instantly: bounce rate < 3%, spam complaints < 0.1%. |
| **Мониторинг блеклистов** | Еженедельная проверка IP и доменов через MXToolbox/MultiRBL. При попадании — вывод из ротации, запрос на delisting. |

---

## 3. Распределение нагрузки

При 1200 ящиках и лимите 30–50 писем/день на ящик:

- **Ёмкость:** 36 000–60 000 писем/день.
- **Распределение по клиентам:** каждому клиенту выделяется пул доменов и ящиков. Пулы не пересекаются — репутационные проблемы одного клиента не затрагивают других.
- **Распределение по направлениям:** внутри пула клиента ящики группируются по кампаниям. Instantly поддерживает иерархию Workspace → Campaign → Mailbox.

## 4. Риски и их закрытие

| Риск | Вероятность | Способ закрытия |
|---|---|---|
| Блокировка домена спам-фильтром | Высокая | Гранулярность: 6–8 ящиков на домен. Потеря одного домена = потеря <1% ёмкости. Резервные домены в запасе. |
| Яндекс 360 меняет политику/цены | Средняя | 20% ящиков на self-hosted Mailcow, можно быстро перебросить нагрузку. |
| Блокировка IP self-hosted | Средняя | Несколько VPS у разных провайдеров (Timeweb + Selectel). Смена IP — вопрос часа. |
| Instantly недоступен из РФ | Низкая | Работа через VPN/прокси. Альтернатива: Smartlead ($39/мес.) или Trigga (российский сервис). |
| Bounce rate > 3% по кампании | Средняя | Верификация базы перед отправкой (ZeroBounce, Snov.io). Лимит 30 писем/день первые 2 недели. |
| Утечка данных клиентов | Низкая | Изолированные пулы, доступ по ролям. Self-hosted — данные на своих серверах. |

### Вариант экономии

Если перевести все 1200 ящиков на self-hosted Mailcow (10–12 VPS по 800 ₽):

| Статья | Сумма |
|---|---|
| Домены | ~6 650 ₽ |
| VPS (12 шт.) | ~9 600 ₽ |
| Instantly | ~9 200 ₽ |
| Warm-up | ~2 990 ₽ |
| Верификация | ~14 250 ₽ |
| **Итого** | **~42 690 ₽/мес.** |

Экономия значительная (×7.5), но требуется DevOps-компетенция для обслуживания 12 серверов, мониторинга IP-репутации и ручного управления DKIM/PTR. Подходит командам с техническим ресурсом.

## Рекомендация

Для старта — **гибридный вариант**: 60% ящиков на Яндекс 360 (надёжность, репутация), 40% на self-hosted (контроль, экономия). По мере набора DevOps-экспертизы — постепенное смещение в сторону self-hosted, снижая ежемесячные расходы до 80–120 тыс. ₽ при полном сохранении ёмкости.
